1. 설명
문제 출제 기관에서는 직종설명서와 아래 사항을 준수하여 2과제를 출제합니다. (아래 사항에 명시되어
있지 않은 부분은 직종설명서를 따르도록 합니다.)
1. 한 기관에서는 4개의 모듈이 포함된 과제 1개를 출제 할 수 있습니다.
2. 과제는 정확히 4개의 각기 다른 모듈을 선택하여 출제합니다.
a. 예) 3개 모듈만 선택하거나 5개 모듈을 선택하여 출제할 수 없습니다. (4개 미선택)
b. 예) Secure networking 모듈을 2문항 출제할 수 없습니다. (동일 모듈 선택)
3. 과제 내의 각 모듈은 서로 독립적이어야 합니다.
a. 같은 리소스를 여러 모듈에서 사용할 수 없습니다.
b. 각 모듈은 모두 서로 다른 리전에서 수행되어야 하며, 문항에 명확하게 기재합니다.
c. 여러 모듈에 거쳐 모든 리소스 이름은 중복되어서는 안됩니다.
4. 대회 시간을 고려해 한 모듈은 60분 이내에 풀이가 가능한 수준이어야 합니다.
5. 2과제의 총점은 30점으로, 각 모듈 별 점수는 7.5점이어야 합니다. (아래 참고)
a. 2과제 총점 30점
i. Module 1 총점 7.5점
ii. Module 2 총점 7.5점
iii. Module 3 총점 7.5점
iv. Module 4 총점 7.5점
6. 하나의 모듈은 여러 개의 채점항목을 가질 수 있으며, 각 채점항목의 배점은 1.5점을 초과할 수
없습니다. (아래 참고)
a. 2과제 총점 30점
i. Module 1 총점 7.5점
ii. 하위채점항목1: 0.1 ~ 1.5점
iii. 하위채점항목2: 0.1 ~ 1.5점
iv. 하위채점항목3: 0.1 ~ 1.5점
7. 한 하위채점항목 채점에는 최대 3분을 넘지 않도록 하며, 대회 운영을 고려해 빠르게 문제와
채점지를 구성합니다.
8. 문제에 애플리케이션이 필요한 경우 Python으로 개발하고 코드를 공개하도록 합니다.
9. 출제 시 아래의 첨부파일들을 제출합니다.
a. (필수) 1개의 문제지 (.hwp 파일)
b. (필수) 1개의 채점지 (.hwp 파일)
c. (필수) 4개의 채점스크립트 (모듈별, .sh 파일)
d. (선택) 바이너리 등 배포 파일 (필요 과제 출제시)
e. (선택) 채점에 필요한 채점파일
10. 문제에서 사용하는 AWS Region은 us-east-1, us-west-1, eu-west-1, eu-central-1,
ap-northeast-2, ap-southeast-1 을 사용합니다.
2. Modules
1. Secure networking
Network Firewall 을 활용하여 VPC의 Ingress/Egress 네트워크 트래픽을 제어하고 검사할 수
있습니다. DNS Query Filtering, Threat Hunting, Egress Web Filtering 등을 예로 들 수
있습니다. 단, Network Firewall 을 단순 트래픽을 전달하는 transparently 형태로 활용하여
별도의 3rd-party tool을 사용하는 것은 금지합니다.
- 필수: VPC, Network Firewall
- 선택: EC2(검증용), Route53
2. NoSQL
DynamoDB를 활용하여 빠른 읽기/쓰기 속도를 제공하고 비정형 데이터를 관리할 수 있는
NoSQL 시스템을 구성합니다. DAX, GSI/LSI, Global Table 등을 예로 들 수 있습니다. 문제를
해결하기 위한 애플리케이션 혹은 코드가 있다면 배포파일로써 제공되어야 합니다. 선수는
NoSQL 서비스에 집중해서 풀 수 있어야 합니다.
- 필수: DynamoDB
- 선택: VPC, EC2, Lambda, Python
3. Cloud governance
EC2 혹은 Security Group에 정책을 위반한 수정이 이뤄지면 이를 감지하여 알림을 보내거나
원래 상태로 복구 하는 Cloud governance를 구성합니다.
- 필수: VPC, EC2
- 선택: Config, EventBridge, SNS, Lambda, CloudWatch, SSM, CloudTrail, IAM
4. CI/CD
EC2 혹은 컨테이너에 앱을 배포할 수 있는 CI/CD 파이프라인을 구성합니다. 웹 서버는 Python
기반 앱이나 HTML(nginx)로 구성하며 코드를 제공하도록 합니다. 하나의 채점항목에 5분을
초과할 수 없음을 고려하여 배포 시간을 설정하고 과제지와 채점지를 작성해야 합니다.
- 필수: Github, GitHub Action
- 선택: ArgoCD, EC2, ECS, EKS, ECR, ELB, Python, HTML(nginx)
5. Real-time data analytics
애플리케이션에서 발생하는 로그 데이터를 기반으로 실시간 데이터 분석 환경을 구성합니다. 로그
발생을 위해 Python 기반 애플리케이션을 배포파일로써 제공해야 하며 서비스 환경으로는
ALB와 EC2를 활용합니다. 실시간 데이터 분석 환경으로는 관리형 서비스인 Managed Service
for Apache Flink 를 사용하며 Flink 애플리케이션을 프로그래밍하는 형태는 금지하며
Notebook 파일에서 SQL 언어로 쿼리를 수행하는 형태로 구성합니다.
- 필수: VPC, EC2, ELB, Managed Service for Apache Flink
- 선택: X
6. CDN
CloudFront를 활용하여 캐싱, 엣지 서비스 등을 제공하는 시스템을 구성합니다. Static asset에
대한 캐싱, Lambda@Edge를 활용한 이미지 리사이징, Function을 활용한 HTTP Header
변경 등 CDN을 활용하는 주요한 케이스들에 대한 시스템을 구성할 수 있습니다. 채점 시 Cache
등 현재 환경에 영향 받지 않도록 문제지와 채점지를 잘 구성해주세요.
- 필수: CloudFront
- 선택: S3, Lambda, ELB, EC2
7. Workflow
데이터 수집/변환/저장 하는 과정에서 Lambda 함수, DynamoDB 등의 서비스를 통합하고
오케스트레이션하기 위해 워크플로우를 구성합니다. 데이터 수집 단계에서는 S3를 활용하여
데이터를 가져오도록 구성하고 처리 단계에서는 Lambda 를 사용하도록 하며 저장 단계에서는
DynamoDB에 데이터를 저장할 수 있도록 구성합니다. 그 과정에서 오케스트레이션을 위한
Workflow를 관리형 서비스는 Step Function을 활용하도록 과제를 구성합니다.
- 필수: S3, Lambda, DynamoDB, Step Functions
- 선택: X
8. Storage data protect
Object Storage인 S3에 저장되는 데이터 보호를 위한 솔루션을 구성합니다. PII 데이터 등의
민감한 데이터 검색 및 조치, Access Point, IAM, Bucket Policy 등을 활용한 접근 제어 등을
예로 들 수 있습니다. 과제를 위해 사용되는 데이터셋은 배포파일로써 제공되어야 합니다.
- 필수: S3
- 선택: Lambda, Macie, IAM
9. logging
ECS Task에서 발생하는 로그를 한 곳에서 확인할 수 있도록 중앙 집중 로깅 솔루션을
구성합니다. 로그 데이터는 파이썬 기반의 애플리케이션을 활용하여 발생시키도록 하며
배포파일로써 제공되어야 합니다. 로그 수집, 가공 과정에 AWS에서 제공하는 로그 드라이버인
awslogs, firelens 를 활용할 수 있으며 로그 저장 및 검색을 위해 Opensearch/Kibana,
Cloudwatch 를 사용할 수 있습니다.
- 필수: ECS
- 선택: CloudWatch, Opensearch/Kibana
10. Message Queue
Message Queue를 활용하는 솔루션을 구성합니다. Spike 트래픽 분산 처리 등의 사례를 예로
들 수 있습니다. 사례를 완전히 구성할 수 없으므로 사례를 가정하는 메시지 생성 애플리케이션을
Python 기반으로 만들어 배포파일로써 제공합니다.
- 필수: SQS, Lambda
- 선택: EC2, Event Bridge, Cloudwatch
11. Monitoring
웹 서비스를 제공해주는 환경에서의 모니터링 솔루션을 구성합니다. 웹 서버는 Python 기반
앱이나 HTML(nginx)로 구성하며 코드를 제공하도록 합니다. 웹 서버 호스팅을 위한 환경으로는
ECS를 사용하며 엔드포인트로써 ELB를 사용합니다. 서비스 수준을 파악할 수 있는
Dashboard를 생성하고 이상치 트래픽에 대한 Alerting 등을 예로 들 수 있습니다.
- 필수: VPC, ECS, ELB
- 선택: Cloudwatch
12. File System security
EFS 시스템의 데이터 보안을 위한 솔루션을 구성합니다. 자격 증명 및 액세스 관리를 예로 들 수
있습니다. EFS 시스템 데이터 보안과 무관한 Linux 시스템 보안 구성이 들어가선 안됩니다.
- 필수: VPC, EC2, EFS
- 선택: IAM
13. WAF
AWS WAF를 이용해 웹 공격을 차단하는 시스템을 구성합니다. 결함이 있는 애플리케이션
코드와 테스트 방법, 자세한 공격 설명을 모두 제시해야 합니다. 과제 해결을 위해 AWS WAF가
아닌 Linux 시스템 또는 3rd-party tool에서 제공하는 솔루션의 사용은 금지합니다.
- 필수: WAF
- 선택: EC2, Lambda, ELB
14. VPC Lattice
애플리케이션 서비스 및 리소스 연결, 보호, 모니터링을 일괄적으로 수행할 수 있는 완전관리형
애플리케이션 네트워킹 서비스인 VPC Lattice를 구성합니다. Python 기반 애플리케이션을
사용하며 배포파일로써 제공되어야 합니다. VPC Lattice 를 구성과 무관한 리소스 사용은
금지합니다.
- 필수: VPC
- 선택: EC2, ELB, DynamoDB
