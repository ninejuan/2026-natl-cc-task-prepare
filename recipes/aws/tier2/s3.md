# S3

**트리거 문구** — "정적 페이지 호스팅", "index.html", "버킷 정책", "Access Point", "버전 관리", "라이프사이클", "PII/민감 데이터"(→ Macie), "모든 퍼블릭 액세스 차단".

**전제**
```bash
export R=ap-northeast-2 ACCT=$(aws sts get-caller-identity --query Account --output text)
```
S3 버킷 이름은 **글로벌 유니크** — 비번호/계정ID 를 붙인다.

---

## 케이스 A — 버전관리 + SSE-KMS + PAB [검증됨]

1과제 기본 버킷(정적 페이지 저장). 퍼블릭 차단 + CMK 암호화 + 버전관리.

```bash
BUCKET=lab-web-$ACCT
aws s3api create-bucket --region $R --bucket $BUCKET --create-bucket-configuration LocationConstraint=$R

# 퍼블릭 완전 차단 (CloudFront OAC 로만 접근하는 케이스)
aws s3api put-public-access-block --bucket $BUCKET --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

aws s3api put-bucket-versioning --bucket $BUCKET --versioning-configuration Status=Enabled

# CMK 암호화 (BucketKey 로 KMS 호출 비용 절감)
aws s3api put-bucket-encryption --bucket $BUCKET --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"aws:kms","KMSMasterKeyID":"<key-arn>"},"BucketKeyEnabled":true}]}'
```

## 케이스 B — 정적 웹 호스팅 [검증됨]

**S3 직접 웹호스팅**(CloudFront 없이). 퍼블릭 허용 필요.

```bash
WEB=lab-web2-$ACCT
aws s3api create-bucket --region $R --bucket $WEB --create-bucket-configuration LocationConstraint=$R
# ★ 웹호스팅은 퍼블릭 필요 → PAB 해제
aws s3api put-public-access-block --bucket $WEB --public-access-block-configuration \
  BlockPublicAcls=false,IgnorePublicAcls=false,BlockPublicPolicy=false,RestrictPublicBuckets=false
aws s3 website s3://$WEB --index-document index.html --error-document error.html
aws s3api put-bucket-policy --bucket $WEB --policy "{\"Version\":\"2012-10-17\",\"Statement\":[{\"Effect\":\"Allow\",\"Principal\":\"*\",\"Action\":\"s3:GetObject\",\"Resource\":\"arn:aws:s3:::$WEB/*\"}]}"
aws s3 cp index.html s3://$WEB/index.html
# 접근: http://<bucket>.s3-website.<region>.amazonaws.com/  (https 아님!)
curl -s "http://$WEB.s3-website.$R.amazonaws.com/"
```
> 1과제는 보통 **S3 웹호스팅 대신 CloudFront+OAC** 다("유저는 CloudFront 로만"). 그때는 케이스 A(PAB 전체 차단) + `../tier1/cloudfront.md` 케이스 A. S3 웹호스팅 엔드포인트는 **HTTP only**(HTTPS 안 됨) — HTTPS 요구면 CloudFront 필수.

## 케이스 C — Access Point [검증됨]

버킷에 여러 접근 경로. VPC 제한·정책 분리에.

```bash
AP=$(aws s3control create-access-point --account-id $ACCT --name lab-ap --bucket $BUCKET \
  --query AccessPointArn --output text)
# VPC 전용으로 제한하려면:
#   --vpc-configuration VpcId=vpc-xxx  → NetworkOrigin=VPC
# Access Point ARN 을 버킷처럼 사용
aws s3api get-object --bucket "$AP" --key f.txt out.txt
```
`NetworkOrigin`: `Internet`(기본) 또는 `VPC`(VpcId 지정 시). 접근 정책은 access point 별로 따로.

## 케이스 D — 라이프사이클 [검증됨]

```bash
aws s3api put-bucket-lifecycle-configuration --bucket $BUCKET --lifecycle-configuration '{
  "Rules":[{
    "ID":"expire-old","Status":"Enabled","Filter":{"Prefix":"tmp/"},
    "Expiration":{"Days":7},
    "Transitions":[{"Days":30,"StorageClass":"STANDARD_IA"},{"Days":90,"StorageClass":"GLACIER"}],
    "NoncurrentVersionExpiration":{"NoncurrentDays":3}
  }]}'
```
tmp/ 는 7일 후 삭제, 30일 IA·90일 Glacier 전환, 구버전 3일 후 삭제.

## 케이스 E — 이벤트 알림 / 복제 / Object Lock

```bash
# 이벤트 알림 (S3 → Lambda/SQS/SNS/EventBridge)
aws s3api put-bucket-notification-configuration --bucket $BUCKET --notification-configuration '{
  "LambdaFunctionConfigurations":[{"LambdaFunctionArn":"<fn>","Events":["s3:ObjectCreated:*"],
    "Filter":{"Key":{"FilterRules":[{"Name":"prefix","Value":"uploads/"}]}}}]}'
# 또는 EventBridge 로: --notification-configuration '{"EventBridgeConfiguration":{}}'

# 교차 리전 복제 (버전관리 필수 + IAM role)
aws s3api put-bucket-replication --bucket $BUCKET --replication-configuration file://repl.json

# Object Lock (WORM, 생성 시 --object-lock-enabled-for-bucket 필요)
```

## 케이스 F — 버킷 정책 패턴

```bash
# HTTPS 강제 (aws:SecureTransport)
{"Effect":"Deny","Principal":"*","Action":"s3:*","Resource":["arn:aws:s3:::B","arn:aws:s3:::B/*"],
 "Condition":{"Bool":{"aws:SecureTransport":"false"}}}
# 특정 VPC endpoint 만
{"Condition":{"StringNotEquals":{"aws:sourceVpce":"vpce-xxx"}},"Effect":"Deny",...}
# CloudFront OAC 만 (../tier1/cloudfront.md 케이스 A)
```

## Terraform [검증됨: 버전관리+SSE+정적호스팅 apply→curl→destroy]

`terraform-s3/main.tf` — **v6 는 버킷 설정마다 별도 리소스**. 정적 웹호스팅 curl 검증(9리소스).

```hcl
resource "aws_s3_bucket" "b" { bucket = "...", force_destroy = true }
resource "aws_s3_bucket_versioning" "v" {          # 버전관리 별도
  bucket = aws_s3_bucket.b.id
  versioning_configuration { status = "Enabled" }
}
resource "aws_s3_bucket_server_side_encryption_configuration" "e" { ... }  # SSE 별도
resource "aws_s3_bucket_public_access_block" "pab" { ... }                 # PAB 별도
resource "aws_s3_bucket_website_configuration" "web" { ... }               # 호스팅 별도
resource "aws_s3_bucket_policy" "p" {
  depends_on = [aws_s3_bucket_public_access_block.pab]   # ★ PAB 먼저, 안 그러면 정책 거부
  ...
}
```
> **v6 검수**: `aws_s3_bucket` 에 versioning/encryption/lifecycle/website 를 인라인으로 넣던 옛 문법은 제거됐다. 전부 `aws_s3_bucket_*` 별도 리소스. 옛 예제를 복사하면 에러.
- `force_destroy = true` 면 destroy 시 버전·객체까지 자동 삭제(버전 버킷 수동 삭제 지옥 회피).

## Console 팁

- **버킷 생성 폼**: 버전관리·암호화·PAB 를 체크박스로 한 화면에(TF 는 리소스 4개).
- **정적 호스팅**: Properties → Static website hosting 활성 + index/error 지정 → 엔드포인트 표시.
- **PAB 경고**: 퍼블릭 정책을 넣으면 콘솔이 "이 버킷은 공개됨" 배지 — 의도 확인.
- **Access Point**: 버킷 → Access Points 탭에서 VPC 제한·정책을 폼으로.

## 함정

- **웹호스팅 = HTTP only** — HTTPS 필요하면 CloudFront. 엔드포인트 형식 `s3-website.<region>` (점 아님).
- **PAB 와 웹호스팅 충돌** — 웹호스팅은 퍼블릭 필요, PAB 는 차단. 목적에 맞게. CloudFront OAC 경로면 PAB 전체 차단이 맞다.
- **버킷 이름 글로벌 유니크** — 비번호/계정ID 필수.
- **복제는 버전관리 양쪽 활성** + IAM role.
- **Access Point ARN 을 --bucket 에** 그대로 넣는다(별도 API 아님).
- **라이프사이클 vs 버전** — 구버전은 `NoncurrentVersionExpiration` 로 따로.
- SSE-KMS 쓰면 **읽는 주체에 kms:Decrypt** 필요.
